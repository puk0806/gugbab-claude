# 사진 → 표 재현 시 회전 방향 먼저 확정

책상 위 종이를 찍은 사진은 대개 회전되어 있다. **몇 도 회전인지 확정하기 전에 레이아웃을
결론내지 않는다.** 90°와 180°를 헷갈리면 행과 열이 통째로 뒤바뀐 표를 만들게 된다.

**Why:**
2026-08-13, 근무표 사진을 180° 회전으로 오판해 "요일=행, 홀/주방=열"인 표를 만들었다.
실제로는 90° CCW 회전이라 "요일=상단 가로, 홀/주방=좌측 세로"가 맞았다. 세로/가로만
바꿔가며 두 번 더 틀린 산출물을 냈고, 사용자가 "사진 안 봤냐"고 지적했다.
회전은 top→bottom(180°)과 top→left(90° CCW)에서 결과가 완전히 다르다.

**How to apply:**
- 회전 판별: **180°는 top→bottom·right→left**, **90° CCW는 top→left·right→top**.
  라벨 스트립이 사진에서 *우측 세로*로 보이면 90° CCW → 실제로는 *상단 가로*다
- 글자가 뒤집혀 보인다는 이유만으로 180°라고 단정하지 말 것 — 90° 회전에서도
  한글은 읽기 어렵게 보인다
- 재현 결과를 PNG로 렌더해 **사진과 같은 방향으로 놓고 육안 대조**한 뒤 전달한다
- 이미 만든 적 있는 양식이면(예: [[pdf-schedule-form-workflow]]) 새로 짜기 전에
  `pdf변환/`의 기존 스크립트를 먼저 확인한다 — 사진이 그 산출물의 인쇄본일 수 있다
- 전달 방식은 [[output-revision-delivery]]
