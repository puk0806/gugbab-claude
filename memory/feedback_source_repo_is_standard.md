자산 존폐의 기준은 언제나 00_gugbab-claude 원본 레포다. 설치된 프로젝트(01 package, 02 voca, 04 health 등)는 원본에 **맞춰 따라오는 쪽**이다.

**Why:** 2026-10-05 voca가 원본에서 09-26 병합 정리된 `frontend/react-virtuoso` 스킬을 재설치 후 로컬 복원하고 "보존 목록에 넣어 달라"고 요청했을 때, 사용자가 "voca에서 사용하고 있다고 해도 불필요한 거면 제거, voca도 최신화해서 불필요한 건 제거하면 된다. 다른 쪽에서 쓰는 것 중 유용한 건 흡수할 수는 있어도 기준은 항상 이 레포"라고 정리함.

**How to apply:**
- 설치본에서 "우리 프로젝트가 쓰니 남겨 달라"는 요청이 와도 프로젝트별 보존 목록·예외를 만들지 않는다. 원본 기준(모델이 이미 아는 일반 지식인지, 고유 제약이 있는지, 다른 자산이 참조하는지)으로 판단한다.
- 판단 결과 불필요하면 설치본에도 남기지 않도록 안내(재설치·수동 삭제). 설치본의 로컬 사본은 기준이 아니다.
- 설치본 쪽에 원본에 없는 유용한 내용(실사용에서 나온 함정·패턴)이 있으면 **원본 스킬로 흡수**(검증·재테스트 거쳐)하고, 설치본은 재설치로 받는다.
- 설치본 세션의 수정 제보는 받아들이되 수정은 원본에서 — 기존 "원본 역류 원칙"과 같은 축. 관련: [[feedback_audit_blind_spots]], [[project_install_architecture]].
