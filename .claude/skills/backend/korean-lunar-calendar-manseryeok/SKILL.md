# 한국 음양력·만세력 (사주 계산 기반)

> 소스: 한국천문연구원(KASI) 천문우주지식정보 / 공공데이터포털 음양력·특일 정보 Open API / usingsky `korean-lunar-calendar` / IANA tz database
> 검증일: 2026-09-10
> 기준 버전: `korean-lunar-calendar` (npm·PyPI) **0.4.0** (2026-06-15 배포), KASI 음양력 Open API (LrsrCldInfoService)

---

## 0. 이 스킬의 전제 — LLM은 만세력을 "추론"할 수 없다

음력 날짜, 절기 절입 시각, 60갑자는 **천문 관측·수치 계산 기반 데이터**다. 규칙이 아니라 값이다.

| 금지 | 이유 |
|------|------|
| 모델이 기억한 음력 날짜를 응답에 넣기 | 윤달 위치는 삭망월·중기의 실측 결과라 규칙으로 유도 불가 |
| 절입 시각(입춘 몇 시 몇 분)을 추정 | 태양 황경 도달 시각은 초 단위 천체력 계산 결과 |
| "대략 2월 4일이 입춘"으로 월주 판정 | 절입 전후 수 분 차이로 월주·연주가 통째로 바뀜 |

**규칙: 모든 날짜·간지·절기 값은 라이브러리 또는 KASI 데이터에서 조회한다. 코드 없이 답하지 않는다.**

## 1. 양력↔음력 변환의 원리와 한계

### 1-1. 원리

한국 음력은 **태음태양력**이다.
- 월(月)의 시작 = 합삭(신월)이 일어나는 날 → 그 달은 29일(소월) 또는 30일(대월)
- 윤달 = 중기(中氣)가 들지 않는 달에 삽입 (무중치윤법)

합삭 시각과 중기 시각은 모두 천문 계산 결과이므로 **닫힌 형태의 공식으로 유도할 수 없고**, 테이블 또는 천체력 엔진이 필요하다.

### 1-2. 지원 범위 한계 (실측 확인)

| 데이터 소스 | 지원 범위 | 확인 경로 |
|------------|----------|----------|
| KASI 음양력 Open API (LrsrCldInfoService) | **1391-02-05 ~ 2050-12-31** | 공공데이터포털·KASI Open API 안내 |
| KASI 웹 음양력 변환 도구 | **-59년 02월 ~ 2050년 12월** | astro.kasi.re.kr 생활천문관 |
| `korean-lunar-calendar` 0.4.0 | 음력 1000-01-01 ~ 2050-11-18 / 양력 1000-02-13 ~ 2050-12-31 | 공식 저장소 README |

**공통 상한이 2050년이다.** 사주 앱은 미래 운세(대운·세운)를 다루므로 2050년 초과 입력을 반드시 명시적으로 거부하거나 별도 엔진으로 분기해야 한다.

### 1-3. 율리우스력/그레고리력 경계

KASI는 **1582년 10월 4일까지 율리우스력, 1582년 10월 5일부터 그레고리력**으로 처리한다.
(율리우스력 1582-10-04의 다음 날이 그레고리력 1582-10-15)

> 주의: 대부분의 프로그래밍 언어 표준 날짜 타입(`datetime`, `Date`)은 **프롤렙틱 그레고리력**을 쓴다. 1582년 이전 날짜를 KASI와 주고받으면 최대 10일 어긋난다. 사주 앱 실무 범위(근현대)에서는 문제되지 않으나, 사료 기반 기능을 넣는다면 반드시 분기 처리한다.

## 2. 사주 4주(四柱)의 경계 규칙 — 음력 날짜가 아니다

**가장 흔한 치명적 오해: "사주는 음력으로 본다" → 틀렸다.**
연주·월주는 **절기력(태양 기준)**, 일주는 **일 단위 60갑자**, 시주는 **시각**으로 결정된다. 음력 날짜는 사주 4주 산출에 직접 쓰이지 않는다.

### 2-1. 연주(年柱) — 입춘 절입 시각 기준

- 연주는 **입춘(태양 황경 315°) 절입 순간**에 바뀐다.
- 양력 1월 1일도, 음력 설날도 아니다.
- 입춘은 대체로 양력 2월 3~5일 사이에 들지만 **연도마다 시·분이 다르다.**

```
1990-02-04 05:00 출생 → (그해 입춘이 05:14라면) 아직 전년 간지
1990-02-04 06:00 출생 → 당년 간지
```

### 2-2. 월주(月柱) — 12절(節)의 절입 시각 기준

24절기 중 **홀수 번째(황경 315°, 345°, 15° … )에 해당하는 12개 "절(節)"**만 월주 경계다. 짝수 번째의 "중기(中氣)"는 음력 윤달 판정에 쓰이며 월주와 무관하다.

| 절(節) | 태양 황경 | 이 절부터 다음 절 전까지의 월지 |
|--------|:---:|:---:|
| 입춘(立春) | 315° | 寅월 |
| 경칩(驚蟄) | 345° | 卯월 |
| 청명(淸明) | 15° | 辰월 |
| 입하(立夏) | 45° | 巳월 |
| 망종(芒種) | 75° | 午월 |
| 소서(小暑) | 105° | 未월 |
| 입추(立秋) | 135° | 申월 |
| 백로(白露) | 165° | 酉월 |
| 한로(寒露) | 195° | 戌월 |
| 입동(立冬) | 225° | 亥월 |
| 대설(大雪) | 255° | 子월 |
| 소한(小寒) | 285° | 丑월 |

**월간(月干)은 연간으로부터 유도된다 (월두법 / 오호둔).**

```
월간_index = (연간_index * 2 + 2 + m) mod 10
  연간_index: 甲0 乙1 丙2 丁3 戊4 己5 庚6 辛7 壬8 癸9
  m: 寅월=0, 卯월=1, ... 丑월=11
```

검증: 甲·己년 → 寅월이 丙寅 (갑기지년 병인두) ✔ / 戊·癸년 → 甲寅 (무계지년 갑인두) ✔

> 주의: 여기서 쓰는 "연간"은 **입춘 기준으로 바뀐 연간**이다. 음력 정월 기준 연간을 넣으면 1월 초·2월 초 출생자가 전부 틀린다.

### 2-3. 일주(日柱) — 60갑자 순환

일진은 60일 주기로 끊김 없이 순환한다. 율리우스적일(JDN)에서 상수 오프셋을 빼고 60으로 나누면 구할 수 있다.

> 주의: **오프셋 앵커 상수를 문헌·블로그에서 베껴 쓰지 말 것.** 반드시 KASI API의 `lunIljin`(일진) 값으로 캘리브레이션 테스트를 작성해 상수를 확정한다. 앵커가 하루만 어긋나도 전체 일주·시주가 통째로 밀린다.

일주가 바뀌는 시각 자체가 **논쟁 대상이다 → §6 참조.**

### 2-4. 시주(時柱) — 2시간 단위 12지, 자시가 23시 시작

| 시지 | 시각 범위 (해당 시점 기준시) |
|:---:|---|
| 子 | 23:00 ~ 00:59 |
| 丑 | 01:00 ~ 02:59 |
| 寅 | 03:00 ~ 04:59 |
| … | 이후 2시간 간격 |
| 亥 | 21:00 ~ 22:59 |

```
시지_index = floor(((hour + 1) mod 24) / 2)        # 子=0
시간_index = (일간_index * 2 + 시지_index) mod 10   # 시두법 / 오서둔
```

검증: 甲·己일 → 子시가 甲子 (갑기일 갑자시) ✔ / 乙·庚일 → 丙子 ✔

## 3. 시각 보정 파이프라인 — 순서를 틀리면 전부 틀린다

사주 계산에서 "출생 시각"은 **벽시계 시각이 아니라 그 지점의 진태양시**다. 아래 순서를 반드시 지킨다.

```
① 입력: 출생 지역의 벽시계 시각 (사용자가 기억하는 그 시각)
        ↓
② 그 시점 그 지역의 법정 시간대 적용 → 절대 시각(UTC instant) 확정
        └ 한국 표준시 변천(+8:30 / +9:00) + 서머타임 자동 반영 필요
        ↓
③ 경도 보정: (출생지 경도 − 그 시점 표준자오선 경도) × 4분/도
        ↓
④ 균시차 보정 (선택 — 유파에 따라)
        ↓
⑤ 진태양시 확정 → 이 값으로 시지·시주 판정
        ↓
⑥ 절입 시각 비교는 ②의 절대 시각(UTC instant)으로 수행 → 연주·월주 판정
```

**②와 ⑤·⑥를 섞지 마라.** 절입 시각 비교는 *천문학적 순간*의 비교이므로 진태양시가 아니라 절대 시각으로 해야 한다. 진태양시 보정은 *시지 판정*에만 쓴다.

### 3-1. ②단계 구현 — tz database를 쓰고 오프셋을 직접 계산하지 마라

```python
from datetime import datetime
from zoneinfo import ZoneInfo

# 벽시계 시각 → 절대 시각. 표준시 변천·서머타임이 tzdb에 담겨 있다.
local = datetime(1959, 6, 15, 23, 30, tzinfo=ZoneInfo("Asia/Seoul"))
instant = local.astimezone(ZoneInfo("UTC"))
offset_minutes = local.utcoffset().total_seconds() / 60   # 그 시점 실제 오프셋
```

> 주의: 일부 런타임·컨테이너의 tzdata 빌드는 **1970년 이전 전이 데이터가 축약**될 수 있다. 배포 환경에서 1954~1961(+8:30 구간)과 서머타임 연도가 실제로 반영되는지 **회귀 테스트로 반드시 확인**한다(§8 T-3). 확인되지 않으면 오프셋 테이블을 애플리케이션에 내장한다.

## 4. 한국 표준시 변천과 서머타임 — 시주 오류의 최대 원인

### 4-1. 표준시 오프셋 이력

| 기간 | 오프셋 | 기준 자오선 |
|------|:---:|---|
| 1908-04-01 ~ 1911 | **UTC+08:30** | 동경 127°30′ |
| 1912-01-01 ~ 1954-03-20 | **UTC+09:00** | 동경 135° |
| 1954-03-21 ~ 1961-08-09 | **UTC+08:30** | 동경 127°30′ |
| 1961-08-10 ~ 현재 | **UTC+09:00** | 동경 135° |

**영향:** 1954~1961년 출생자는 당시 벽시계가 UTC+8:30이었다. 이 구간을 UTC+9로 처리하면 시각이 30분 어긋나 경계 출생자의 **시주가 통째로 바뀐다.** 반대로 이 구간은 기준자오선이 127°30′이라 서울의 경도 보정량이 거의 0에 가까워진다(§5).

### 4-2. 서머타임(일광절약시간) 실시 시기

| 실시 시기 | 비고 |
|---|---|
| **1948 ~ 1951** | 여름철(대략 6~9월 구간) 시행 |
| **1955 ~ 1960** | 여름철(대략 5~9월 구간) 시행. 당시 기준이 UTC+8:30이므로 **적용 시 UTC+9:30** |
| **1987 (5.10 ~ 10.11)** | 서울올림픽 대비 시범 |
| **1988 (5.08 ~ 10.09)** | 올림픽 기간. 기준 UTC+9 → **적용 시 UTC+10:00** |

> 주의: 1988년 시행 기간(5월 8일 ~ 10월 9일)과 UTC+10 적용은 복수 소스에서 일치 확인되었다. **1948~1951·1955~1960·1987의 연도별 정확한 시작·종료 일자는 소스마다 표기가 달라 미확정이다.** 하드코딩하지 말고 `Asia/Seoul` tz 데이터를 단일 진실 공급원으로 사용하고 §8 T-3 테스트로 실제 오프셋을 고정한다.

**영향:** 서머타임 기간 출생자는 벽시계 시각이 실제 태양시보다 1시간 앞서 있다. 보정하지 않으면 **시주가 한 칸(또는 두 칸) 밀린다.** 1988년 여름 출생자는 한국 사주 앱에서 가장 흔한 오류 케이스다.

## 5. 진태양시 보정 — 경도 + 균시차

### 5-1. 경도 보정

```
경도보정(분) = (출생지_경도 − 표준자오선_경도) × 4
```

현행 표준자오선은 동경 135°다. 서울(약 동경 126.98°) 기준:

```
(126.98 − 135) × 4 ≈ −32.1분   → 서울의 평균태양시는 KST보다 약 32분 늦다
```

| 지역 | 대략 경도 | 135° 기준 보정 |
|---|:---:|:---:|
| 인천 | 126.7° | 약 −33분 |
| 서울 | 127.0° | 약 −32분 |
| 대전 | 127.4° | 약 −30분 |
| 대구 | 128.6° | 약 −26분 |
| 부산 | 129.0° | 약 −24분 |
| 울릉·독도 | 130.9° | 약 −16분 |

> **"무조건 −30분" 관행의 정체:** 실무에서 널리 쓰이는 −30분은 한반도 평균에 가까운 근사값이다. 유파에 따라 ⑴ −30분 일괄 적용 ⑵ 출생지 경도별 정밀 적용 ⑶ 국가 표준시를 그대로 쓰고 경계 시각에서만 참고 — 세 입장이 갈리며 **합의된 정설은 없다.**
>
> **구현 요구사항:** 보정 방식을 **설정으로 노출**하고, 계산 결과에 "어떤 보정을 적용했는지" 메타데이터를 반드시 동봉한다. 하나로 고정하면 다른 만세력과 결과가 달라졌을 때 원인 추적이 불가능하다.

> 주의: 1954-03-21 ~ 1961-08-09 구간은 표준자오선이 **127°30′**이었다. 이 구간에 135° 기준 −32분을 적용하면 **이중 보정**이 된다. 경도 보정의 기준자오선은 반드시 §4-1의 그 시점 기준자오선을 써야 한다. 실제로 매우 흔한 버그다.

### 5-2. 균시차(Equation of Time)

지구 자전축 경사와 궤도 이심률 때문에 진태양시와 평균태양시는 연중 최대 **+16분 33초(11월 3일경) ~ −14분 06초(2월 12일경)** 차이가 난다.

- 경도 보정만 하면 **평균태양시**, 균시차까지 더하면 **진태양시**다.
- 균시차까지 적용하는 유파와 경도 보정만 하는 유파가 갈린다.
- 최대 ±16분 → **시지 경계 부근에서 결과가 바뀔 수 있다.**

**구현 요구사항:** 균시차 적용 여부도 설정으로 노출한다. 균시차 값은 자체 근사식을 임의로 쓰지 말고 천체력 라이브러리에서 얻거나, 근사식 사용 사실을 결과 메타데이터에 명시한다.

## 6. 야자시(夜子時)·조자시(朝子時) 논쟁

23:00~23:59 출생자의 **일주(日柱)를 어느 날로 볼 것인가**에 대한 미해결 논쟁이다.

| 관법 | 23:00~23:59 출생의 일주 | 그때의 시주 | 00:00~00:59 출생의 일주 |
|---|---|---|---|
| **정자시(正子時)** | **다음 날** 일주 (하루가 23시에 시작) | 다음 날 일간 기준 자시 | 다음 날 일주 |
| **야자시/조자시 구분** | **당일** 일주 유지 (= 야자시) | 다음 날 일간 기준 자시 | 다음 날 일주 (= 조자시) |

**공통점:** 23:00~23:59의 **시주**는 양쪽 다 "다음 날 일간 기준 자시"를 쓴다.
**차이점:** **일주**를 당일로 볼지 다음 날로 볼지.

이 논쟁은 오늘날까지 결론이 나지 않았다.

**구현 요구사항:**
- `zishiMode: "true_zi" | "night_zi"` 같은 설정으로 노출하고 **기본값을 문서화**한다.
- 23:00~23:59 출생은 결과에 "관법에 따라 일주가 달라지는 구간"이라는 플래그를 반드시 포함한다.
- 이 플래그를 UI에 노출하지 않으면 "다른 앱과 결과가 다르다"는 CS가 반복된다.

> 주의: 진태양시 보정(§5)을 적용하면 벽시계 23:20 출생이 진태양시 22:48이 되어 **자시가 아니게 될 수도 있다.** §3의 파이프라인 순서(진태양시 확정 → 시지 판정)를 지켜야 일관된다.

## 7. 검증된 데이터 소스·라이브러리 (2026-09-10 실접속 확인)

### 7-1. 1순위 — 한국천문연구원(KASI) 공식

| 소스 | 내용 | 범위 | 사주 적용 시 주의 |
|---|---|---|---|
| **음양력 정보 Open API** (`LrsrCldInfoService`, 공공데이터포털 데이터 `15012679`) | 양→음(`getLunCalInfo`), 음→양(`getSolCalInfo`), 특정 음력일(`getSpcifyLunCalInfo`), 율리우스적일(`getJulDayInfo`). 응답에 `lunSecha`(세차)·`lunWolgeon`(월건)·`lunIljin`(일진)·`lunLeapmonth`·`solJd` 포함 | 1391-02-05 ~ 2050-12-31 | **일진(`lunIljin`)만 사주 일주 검증에 직접 사용 가능** — 아래 경고 참조 |
| **특일 정보 Open API** (`SpcdeInfoService`, 데이터 `15012690`) | 국경일·공휴일·기념일·**24절기**·잡절 | 명시 범위 미확인 | 24절기 응답에 절입 "시각"이 포함되는지 **소스 간 진술이 엇갈림** — 아래 경고 참조 |
| **KASI 역서(曆書)** | 매년 발행. 24절기 절입 시각 수록. **서울 국가기준점, 한국 표준시(UTC+9) 기준으로 계산** | 발행 연도별 | 절입 시각의 **최종 권위 소스.** 회귀 테스트 기대값의 출처로 삼는다 |
| KASI 생활천문관 음양력 변환 웹 도구 | 양음력·간지·율리우스일 대조 | -59년 02월 ~ 2050년 12월 | 수동 대조 검증용 |

> **주의(미검증 — 반드시 회귀 테스트로 확인):** KASI 음양력 API의 `lunSecha`(세차)·`lunWolgeon`(월건)은 **음력 연·월에 붙는 간지**로 보이며, 사주의 **입춘 기준 연주·절기 기준 월주와 다를 가능성이 높다.** 그대로 연주·월주로 쓰면 1~2월 출생자와 절입 경계 출생자가 대량으로 틀린다. 구현 전 반드시 확인한다:
> - 입춘 직전 날짜(예: 어느 해 2월 2일)의 `lunSecha`가 전년 간지인지 당년 간지인지
> - 음력 12월 말일 ↔ 음력 1월 1일 사이 `lunSecha` 변화 시점
>
> 확인 결과가 위 추정과 같다면 **연주·월주는 절기 데이터로 직접 계산하고, KASI는 일진 검증 용도로만 사용**한다.

> **주의(DISPUTED):** 특일 정보 API의 24절기 응답에 절입 시각(시:분)이 포함되는지 소스 진술이 엇갈린다. (A) "응답은 `locdate`·`dateName` 등 날짜 중심이며 시각 없음" (B) "절기 시각·태양 황경까지 제공"(이 API를 소비하는 파생 공개 데이터셋 문서 기준). **날짜만 있으면 사주에는 무용하다.** 구현 착수 시 실제 응답 1건을 받아 필드를 직접 확인하고, 시각이 없으면 KASI 역서 기반 절입 시각 테이블을 별도로 구축한다.

## 8. 검증 전략 — KASI 대조 회귀 테스트

계산 결과는 "그럴듯함"이 아니라 **공식 데이터와의 일치**로만 검증된다. 정상 케이스만 통과하는 테스트는 미완성이다.

### 8-1. 필수 테스트 케이스

| ID | 계층 | 내용 | 기대 |
|---|---|---|---|
| **T-1** | 정상 | 임의 날짜 300건 이상 음↔양 변환을 KASI API 응답과 대조 | 100% 일치 |
| **T-2** | 정상 | 라이브러리 절기 시각 vs KASI 역서 절입 시각 (최근 30년) | UTC 정규화 후 일치. 1시간 계통 오차 발견 시 시간대 표기 문제 |
| **T-3** | 경계 | `Asia/Seoul`로 1955·1959·1988년 여름 시각의 실제 `utcoffset` 확인 | 1955·1959 여름 → +9:30 계열 / 1988 여름 → +10:00 / 1960-01 → +8:30. **런타임 tzdata 축약 여부 검출** |
| **T-4** | 경계 | 입춘 절입 시각 **1분 전 / 1분 후** 출생 | 연주·월주가 정확히 그 순간에 전환 |
| **T-5** | 경계 | 12절 각각의 절입 ±1분 (24 케이스) | 월지가 §2-2 표대로 전환 |
| **T-6** | 경계 | 22:59 / 23:00 / 23:59 / 00:00 / 00:59 출생 | 정자시·야자시 두 모드 각각의 기대 일주·시주를 명시적으로 고정 |
| **T-7** | 경계 | 윤달 있는 해의 윤달 1일·말일, 윤달 직전·직후 달 | 윤달 플래그 정확, 평달과 혼동 없음 |
| **T-8** | 경계 | 1954-03-21, 1961-08-10 (오프셋 전환일) 00:00·23:59 | 오프셋 전환 반영 + 경도 보정 기준자오선도 함께 전환 |
| **T-9** | 경계 | 대월/소월 경계(음력 29일↔30일), 12월 말~1월 초 | 월 넘김 오류 없음 |
| **T-10** | 이상 입력 | 2051년, 1300년, 2월 30일, 윤달 없는 달에 `isIntercalation=true`, null·빈 문자열·초장문·비ASCII | **예외 또는 명시적 실패.** 조용한 오답 절대 금지 |
| **T-11** | 이상 입력 | 존재하지 않는 시각(서머타임 시작으로 건너뛴 시각) | 명시적 처리(거부 또는 정책적 보정) — 조용히 임의 해석 금지 |
| **T-12** | 이상 입력 | 서머타임 종료로 **중복되는 시각** | 어느 쪽으로 해석했는지 결과 메타데이터에 명시 |
| **T-13** | 악성 입력 | KASI API 응답 위조·필드 누락·타임아웃·429 | 캐시 폴백 또는 명시적 에러. **부분 데이터로 사주를 만들어 반환 금지** |
| **T-14** | 악성 입력 | 사용자 입력 좌표 극단값(경도 9999, NaN, −180) | 검증 후 거부. 경도 보정 식에 그대로 흘리지 않음 |

### 8-2. 테스트 데이터 구축 원칙

```
1. KASI API·역서에서 받은 원본 응답을 그대로 픽스처로 저장 (재현 가능성)
2. 테스트 실행 시 외부 API를 호출하지 않는다 (KASI 장애·쿼터로 CI가 깨짐)
3. 대신 "픽스처 갱신 잡"을 별도 스케줄로 돌려 원본과의 drift를 감지
4. 기대값을 구현 코드로 생성하지 않는다 — 반드시 외부 공식 소스에서 가져온다
```

> **금지:** 테스트를 통과시키려고 기대값을 구현 출력으로 덮어쓰는 것. 그 순간 이 테스트는 아무것도 검증하지 못한다.

### 8-3. 다른 만세력과 결과가 다를 때 진단 순서

```
1. 연주가 다르다      → 입춘 절입 시각 기준인가? 음력 설 기준으로 잘못 계산했나?
2. 월주가 다르다      → 절기 시각 시간대(UTC+8 vs +9) 확인, 중기/절 혼동 확인
3. 일주만 하루 차이   → 23:00~23:59 구간인가? (야자시/조자시 관법 차이)
4. 시주만 다르다      → 서머타임·표준시 변천·진태양시 보정 설정 차이
5. 30분 안팎 차이     → 경도 보정 방식(−30분 일괄 vs 경도별) 차이
6. 1954~1961년생      → 기준자오선 이중 보정 버그 의심
```

## 9. 흔한 실수 체크리스트

- [ ] 음력 날짜로 사주를 세운다 → **틀림.** 절기력 기준이다
- [ ] 입춘을 "2월 4일"로 하드코딩 → 연도별 시·분이 다르다
- [ ] 24절기 전부를 월주 경계로 쓴다 → **12절만** 해당, 중기는 아니다
- [ ] 중국권 라이브러리 절기 시각을 KST로 착각 → 1시간 계통 오차
- [ ] 1954~1961년생에 UTC+9 적용 → 30분 오차
- [ ] 1954~1961년생에 135° 기준 경도 보정 → 이중 보정
- [ ] 1988년 여름 출생자에 서머타임 미적용 → 1시간 오차
- [ ] 절입 시각 비교를 진태양시로 수행 → 절입은 절대 시각으로 비교해야 함
- [ ] 23시대 출생자에 관법 플래그 미노출 → 반복 CS
- [ ] 2050년 초과 입력을 조용히 처리 → 데이터 범위 밖, 명시적 거부 필요
- [ ] 보정 방식을 코드에 고정 → 결과 재현·원인 추적 불가. 설정 + 메타데이터로 노출
- [ ] 일진 앵커 상수를 블로그에서 복사 → KASI `lunIljin`으로 캘리브레이션 테스트 필수

## 10. 결과 스키마 권장 형태

계산 결과에는 **입력 해석과 적용한 관법**을 반드시 동봉한다. 이것이 없으면 어떤 검증도 불가능하다.

```jsonc
{
  "input": { "wallClock": "1988-07-15T23:30:00", "tz": "Asia/Seoul", "birthPlace": { "lon": 126.98 } },
  "resolved": {
    "utcInstant": "1988-07-15T13:30:00Z",
    "appliedOffsetMinutes": 600,            // 서머타임 반영 결과 (+10:00)
    "dstApplied": true,
    "standardMeridian": 135,
    "longitudeCorrectionMinutes": -32.1,
    "equationOfTimeMinutes": -5.8,          // 적용 안 하면 null
    "trueSolarTime": "1988-07-15T22:52:06"
  },
  "policy": {
    "longitudeMode": "per_location",        // per_location | fixed_minus_30 | none
    "equationOfTime": true,
    "zishiMode": "true_zi"                  // true_zi | night_zi
  },
  "pillars": { "year": "…", "month": "…", "day": "…", "hour": "…" },
  "flags": ["ZISHI_BOUNDARY", "DST_PERIOD"],
  "dataSource": { "solarTerms": "KASI-yeokseo-1988", "lunar": "korean-lunar-calendar@0.4.0" }
}
```
