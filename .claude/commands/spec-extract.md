$ARGUMENTS 범위(레포 경로·모듈·화면)의 레거시 코드에서 마이그레이션·재구축용 스펙을 추출해 문서로 남겨.

$ARGUMENTS가 없으면 현재 레포 전체를 대상으로 하되, 먼저 범위(전체 / 모듈 / 화면)를 물어봐.

**진행 순서**
1. 시작 전 확인: 대상 범위, 스택(자동 감지 결과), 산출 위치(기본 `docs/spec/`)를 요약하고 "진행할까요?"로 확인받는다
2. 추출: `legacy-spec-extractor` 에이전트에 범위를 넘긴다 — 방법론·양식은 `spec-extraction-method` 스킬, 스택별 추출법은 설치된 `spring-mybatis-spec-extraction` · `react-spec-extraction` · `nexacro-17-xfdl-anatomy` 스킬을 따른다
3. 검토: `spec-reviewer` 에이전트로 근거 누락·불일치·CRUD 완전성을 검사한다
4. 보고: `docs/spec/README.md`의 요약(단위 수·확신도 분포·미확인 목록·사람 검토 필요 항목)과 검토 판정을 보여준다

**지켜야 할 것**
- 소스 코드를 수정하지 않는다 — 산출물은 `docs/spec/` 아래 문서만
- 모든 항목에 근거(파일:줄)·확신도(확인됨/추정/미확인)·사용 여부를 붙인다
- 비밀번호·키·접속 정보 값은 문서에 옮기지 않는다
- 레포의 빌드·스크립트를 실행하지 않는다
- 커밋은 하지 않는다 (요청 시 `/commit`)
