# 깨끗한 Claude 리뷰 (Codex 리뷰가 돌지 않을 때)

> 2026-11-23 사용자 결정: Codex 리뷰를 하지 않는 모든 경우(묶음 꺼짐·`codex.skipReview`·CLI 없음·미로그인·계정 400)에
> 대화 맥락 없는 Claude 리뷰어 `clean-reviewer` 가 대신 적대적 리뷰를 한다. **코드를 바꾼 턴이 끝날 때마다**, 모든 프로젝트 기본 켬.
> 참고: Google Elephant-Goldfish Model — 맥락을 다 아는 작성자(코끼리) 대신 맥락 없는 리뷰어(금붕어)가 검토한다.

## 언제 도나

`clean-review-guard` 훅(Stop)이 정한다. 직접 먼저 부르지 않는다 — 훅이 준 요청문으로 부른 것만 리뷰로 인정된다.

| 리뷰함 | 건너뜀 |
|---|---|
| 이번 턴에 코드 파일(`.ts`·`.js`·`.py`·`.java`·`.sh`·`.sql` 등)을 바꿈 | 문서·설정만 바꿈 |
| Codex 리뷰가 돌지 않음 | Codex 리뷰가 실제로 돌 상황(codex 묶음 켬 + 로그인 + 사용 가능) |
| | git 레포 아님 |

## 진행 (훅이 막으면 사용자에게 묻지 말고 바로)

1. **Agent 도구**로 `subagent_type: "clean-reviewer"` 를 부른다. 백그라운드로 돌면(대화형 세션의 기본) 완료 알림이 올 때까지 기다렸다가 그 결과로 판정한다 — 도는 동안에는 훅이 다시 막지 않는다
2. `prompt` 는 훅이 `===== <요청 ID> 시작` 과 `===== <요청 ID> 끝` 사이에 준 요청문을 **한 글자도 바꾸지 않고** 그대로 넣는다
   - 설명·작업 의도·"이건 괜찮다" 같은 말을 덧붙이면 리뷰어가 맥락에 끌려간다 → 훅이 요청문과 다르면 인정하지 않는다
3. 지적마다 판정한다 — 리뷰를 맹목적으로 받아들이지 않는다
   - **ACCEPT**: 타당 → 고치고 수용 이유를 적는다
   - **REJECT**: 근거 없음·설계 의도와 충돌 → 반박 근거를 적고 고치지 않는다
   - **PARTIAL**: 일부만 타당 → 나눠서 판정
4. 고쳤으면 다시 끝낸다 → 훅이 다음 라운드 요청문을 준다. **최대 3라운드**, 새 심각 지적이 없으면 거기서 끝난다
5. 사용자에게 아래 형식으로 보고한다

```
## 깨끗한 리뷰 요약 ({N}라운드)

### ✅ ACCEPTED (고침)
- [지적]: [고친 내용] — 수용 이유

### ❌ REJECTED (반박)
- [지적]: [반박 근거]

### ⚠️ 잔존 이슈
- 있으면 나열 / 없음
```

## 인정되지 않는 것 (훅이 막는다)

- 표시 파일을 만들거나 "검토했다" 고 쓰기만 한 것
- `general-purpose` 등 다른 에이전트로 리뷰한 것, 오류·중단으로 끝난 호출, 완료 기록(Claude Code 가 남기는 결과 상태·완료 알림)이 없는 호출
- 마지막 코드 변경보다 **먼저** 시작한 리뷰
- 요청문을 바꾸거나 덧붙인 호출

## 알려진 한계

- **이 세션에 리뷰어가 없을 때**(세션 중 업데이트로 훅만 먼저 바뀜): 호출이 "not found" 로 실패하면 재시작 안내 후 통과한다. `/exit` 후 다시 시작하면 리뷰한다
- **Codex 가 맡을 상황**(Codex 묶음 켬 + 로그인 + 사용 가능)이면 이 훅은 비켜선다. 그때 Codex 리뷰가 실제로 돌았는지는 `codex-review-guard` 가 맡는다(그 훅의 한계는 그 훅 문서)
- "이번 턴에 바뀐 코드" 는 파일 수정 시각으로 판단한다 — 수정 시각을 일부러 과거로 돌리면 피할 수 있고, 시계가 어긋나 미래 시각인 파일이 있으면 3라운드 상한까지 요구한다. 지운 파일은 남아 있는 상위 폴더의 수정 시각을 쓰므로, 지난 턴에 지운 파일이 있는 폴더에 이번 턴 새 파일이 생기면 리뷰를 한 번 더 요구할 수 있다(안전한 쪽)

- **리뷰 대상 확장자**는 `codex-review-guard` 와 같다(`.ts`·`.js`·`.py`·`.java`·`.go`·`.rs`·`.sh`·`.bash`·`.zsh`·`.bat`·`.cmd`·`.ps1`·`.sql`·`.vue`·`.svelte`·`.php` 등, 대소문자 무관). 목록에 없는 확장자만 바꾼 턴은 리뷰하지 않는다
- **요청문 기록**은 임시 폴더의 세션별 상태 파일에 둔다(링크는 거부). 이 파일을 직접 고쳐 쓰면 다른 요청문도 인정되므로, 일부러 속이는 것까지 막지는 못한다

## 끄기

`/harness` 에서 "깨끗한 리뷰" 묶음을 끈다 (훅·룰·에이전트가 함께 꺼진다). Codex 리뷰를 쓰려면 Codex 리뷰 묶음을 켜고 로그인한다 — 그때는 Codex 가 맡고 이 리뷰는 건너뛴다.
