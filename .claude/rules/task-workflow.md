# 작업 착수 전 확인 절차

복잡한 작업(구현·설계·추가·변경·개편 등)을 시작하기 전에 반드시 아래 순서를 지킨다.

> **훅으로 강제된다 (`task-confirm-guard`)**: 직전 답변의 **마지막 줄**이 "진행할까요?"이고
> 사용자가 승인해야 Write/Edit/NotebookEdit 가 허용된다. 승인 전 파일 수정은 차단된다.
> **셸 명령도 같다**: 승인 전에는 Bash·Monitor 로 파일을 바꾸는 명령(리다이렉트·cp·mv·rm·sed -i·tee, 쓰기 코드가 든 python·node 인라인/스크립트, 쓰는 npm 스크립트, git checkout·stash 등)도 막힌다. 읽기·임시 폴더 쓰기와 이름이 고정된 테스트 실행은 그대로 된다(스크립트 이름이 변수인 반복문 `for t in $(…); do node "$t"` 은 내용을 판정할 수 없어 승인 전엔 막힌다).
> 승인된 동안 띄운 서브에이전트는 메인 대화에 새 메시지가 와도 끝날 때까지 승인이 유지된다(거절·중단하면 함께 풀림). 승인 전에 띄운 서브에이전트는 수정이 막힌다.
> 거절·수정 요청("아니", "말고", "다시 정리" 등)이나 승인 표현 없는 되묻기는 승인이 아니다 → 계획을 고쳐 다시 묻는다.
> 사용자가 "바로 진행"·"확인 없이"·"물어보지 말고"·"컨펌 없이"·"그냥 진행/만들어/해줘"라고 하면 생략된다(바로 뒤에 "하지 마" 같은 부정이 오면 생략 아님). 메모리·계획·임시 폴더 쓰기는 항상 허용.
> 여러 파일에 걸친 대규모 작업은 네이티브 **Plan Mode**를 써도 된다 (계획 승인 버튼은 자동 승인 — "진행할까요?"가 확인을 대신한다).

---

## 필수 순서

### 1단계: 이해 확인
"이렇게 이해했습니다:" 형식으로 요청 내용을 1-3줄로 요약한다.

### 2단계: 작업 목록 리스트업
번호 있는 구체적 단계 목록을 제시한다.

```
1. ...
2. ...
3. ...
```

### 3단계: 사용자 확인 대기
"진행할까요?" 로 확인을 요청하고 **승인 전 코드·파일 수정 금지**.
"진행할까요?"는 답변의 **마지막 줄**에 따옴표 없이 쓴다 — 본문 중간이나 인용 형태는 훅이 승인 질문으로 인정하지 않는다.

### 4단계: 승인 후 실행

## 예외 — 즉시 실행 가능

| 예외 유형 | 예시 |
|----------|------|
| git 커밋·푸시 | "커밋해줘", "푸시해줘" |
| 내용 요약·설명 | "요약해줘", "설명해줘", "알려줘" |
| 단순 조회 | "읽어줘", "찾아줘", "보여줘" |
| 1줄 단순 수정 | 오탈자 수정, 변수명 변경 1건 — **단, 훅은 수정 크기를 구분하지 못해 차단한다.** 사용자가 "바로 수정해"처럼 생략을 명시했을 때만 즉시 실행, 아니면 짧게라도 "진행할까요?"를 거친다 |
