# 1.1.6 버전마다 릴리스 노트 자동 생성

날짜: 2026-11-17 · 기준: `ce361ae` (v1.1.5)

## 수 변화

- **스킬:** 그대로 · **에이전트:** 10 → 11 (`clean-reviewer` 추가)
- **훅:** 30 → 31 (`clean-review-guard` 추가) · **룰:** 14 → 15 (`clean-review.md` 추가) · **커맨드:** 그대로 (`release-version-guard` 훅과 `/create-pr` 커맨드 내용도 바뀜)

## 큰 수정 내용

- **버전마다 릴리스 노트를 남깁니다.** 노트는 `docs/release-notes/<버전> <핵심 수정 요약>.md` 입니다. 이 파일이 이번 버전의 노트이고, 이 방식으로 만든 첫 노트입니다.
- **`node scripts/release-version.js notes --title "핵심 수정 요약"`** 이 초안을 만듭니다. 초안에는 날짜와 기준 커밋, 스킬·에이전트·훅·룰·커맨드의 수 변화, `origin/main` 이후 커밋 제목이 들어갑니다. 커밋 제목은 분류별로 묶고, 버전 올림과 세션 요약 동기화 커밋은 뺍니다. `bump` 도 끝에 이 명령을 부릅니다(`--no-notes` 로 끔).
- **안전장치:** 요약의 위험 글자는 지우고 50자로 자릅니다. 같은 버전 노트는 덮어쓰지 않고, 노트 폴더가 링크면 쓰지 않습니다.
- **노트를 빠뜨리면 PR 을 막습니다.** `gh pr create` 때는 `release-version-guard` 가, PR 마다 `version-check` 워크플로(`notes-check`)가 확인합니다.
- **머지되면 이 노트가 GitHub Release 본문과 제목이 됩니다.** 노트가 없던 예전 버전은 지금처럼 PR 목록을 자동으로 만듭니다.
- **Claude 가 스스로 만든 임시 폴더는 묻지 않고 지웁니다.** 같은 명령에서 `T=$(mktemp -d …)` 로 만든 폴더 안에 쓰고 `rm -rf "$T"` 로 지우는 것은 확인 창 없이 됩니다. 변수를 다시 정하거나, 조건 안에서 만들거나, mktemp 를 바꿔치기하는 형태는 지금처럼 묻습니다.
- **쓸데없는 확인 창을 훅이 막습니다.** 읽기만 하는 조사 명령(`awk` 출력, `ps`, 반복문 앞 고정 변수, `gugbab-claude status`)은 자동 허용합니다. 그 밖에 확인 창이 뜰 명령은 Claude 가 실행하기 전에 훅이 거부하고 다시 쓰게 합니다. 꼭 필요할 때는 답변과 명령 설명에 "확인 창" 을 적어 미리 알린 뒤에만 뜹니다.
- **소스 파일을 `python3`·`node` 코드로 고치지 못하게 막습니다.** 코드 안에서 프로젝트 소스·설정·문서 파일에 쓰면(`open(p,'w')`·`writeFileSync` 등) 확인 창이 뜨기 전에 거부합니다. 그러면 Claude 가 같은 수정을 Edit 도구로 다시 해서 `acceptEdits` 에서는 확인 창이 뜨지 않습니다. 읽기만 하는 코드, 임시 폴더 쓰기, 경로를 알 수 없는 코드는 그대로 둡니다. 과거 명령 8,288건을 재생하니 203건이 이 경우였습니다.
- **프로젝트 안 셸 스크립트 실행은 묻지 않습니다.** `sh scripts/x.sh` 처럼 프로젝트 안에 있는 스크립트 파일을 `sh`·`bash`·`zsh`·`dash` 로 돌리면 `node scripts/x.js` 처럼 확인 창 없이 됩니다. `sh -c "…"`·표준입력으로 넘긴 코드·임시 폴더나 프로젝트 밖 스크립트·밖을 가리키는 링크는 지금처럼 묻습니다.
- **`git stash` 를 막습니다.** 되돌리다 실패하면 작업이 사라질 수 있어서입니다. 목록·내용 보기는 됩니다.
- **보호 파일을 Bash 로 옮기거나 지우지 못합니다.** `SKILL.md`·`verification.md`·`memory/` 는 경로에 변수가 있거나 그 파일이 든 폴더째여도 막습니다.
- **하네스 제작 묶음을 기본으로 끕니다.** 스킬·에이전트 형식 검사, README 검사, 검증일 알림, 제작 규칙 4개, `/agent-status`, `skill-tester` 입니다. 앱 프로젝트에서 README 검사와 삭제 검사가 서로 막아 작업이 멈추던 문제 때문입니다. 이 레포는 `.gugbab.json` 으로 그대로 켜 둡니다. 다른 프로젝트에서 필요하면 `/harness` 에서 켭니다.
- **Codex 리뷰를 기본으로 끕니다.** 켜 두었던 프로젝트도 모두 껐습니다. 필요하면 `/harness` 에서 다시 켭니다.
- **Codex 리뷰가 돌지 않으면 깨끗한 Claude 리뷰어가 대신 리뷰합니다.** 코드를 바꾼 턴이 끝날 때, 대화 맥락을 모르는 `clean-reviewer` 에이전트가 사용자 요청 원문과 바뀐 파일만 보고 배포를 막을 결함을 찾습니다(구글 Elephant-Goldfish Model 참고). Claude 는 지적마다 고치거나 반박하고 요약을 보고합니다. 최대 3라운드입니다. 훅이 준 요청문 그대로 실제로 리뷰어를 부른 기록이 있어야 끝낼 수 있습니다. 모든 프로젝트에서 기본으로 켜지며, `/harness` 의 "깨끗한 리뷰" 묶음으로 끕니다. 리뷰 대상은 셸·PowerShell·SQL·Vue 파일까지이고, 답변이 끝나기 전에 커밋한 코드도 포함합니다.
- **훅이 잘못 막던 경우 3가지를 고쳤습니다.** "다른 건 신경쓰지 말고 다 진행해" 처럼 금지와 실행 지시가 함께 있는 승인을 거절로 읽던 것, 레포 `memory/` 미러 수정이 승인 전에 막히던 것, 코드 안 화살표 함수(`=>`)와 `SKILL.md` 글자가 함께 있으면 읽기 전용 `node -e` 가 막히던 것입니다.
- **Claude 가 띄운 프로세스는 묻지 않고 끕니다.** `pkill`·`killall` 이 끌 대상을 실행 전에 확인해, 전부 이 세션이 띄운 것이면 확인 창 없이 됩니다. 다른 프로세스가 하나라도 섞이면 묻습니다.
