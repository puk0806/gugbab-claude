**1. 배당금 받을 때 (가장 흔한 용례)**

- 예: 배당 100,000원 → 제세금 15,400원 공제 → 실수령 84,600원

- **증권거래세**: 매도 금액에 부과 (2025년 기준 코스피 0.15%·농특세 포함, 코스닥 0.15%)
- 국내 상장주식은 소액주주라면 매매차익에 양도소득세가 없지만, **대주주**이거나 **해외주식**이면 양도소득세(해외주식은 연 250만 원 공제 후 22%)가 붙습니다.

정리하면, 제세금은 특정 세금 하나의 이름이 아니라 **"떼야 할 세금 전부"를 묶어 부르는 표현**이고, 배당 맥락이면 사실상 15.4% 원천징수를 가리킨다고 보면 됩니다.

```
그림자&!다이맥스
```

- `그림자` — 그림자(섀도우) 포켓몬만 표시
- `&` — 조건 AND 연결
- `!` — 제외(NOT). `!다이맥스`는 다이맥스 가능 포켓몬 제외

거다이맥스까지 같이 빼고 싶으면:

```
그림자&!다이맥스&!거다이맥스
```

참고로 검색어는 한국어 클라이언트 기준이고, `&` 대신 `,`를 쓰면 OR(둘 중 하나)이 되니 반드시 `&`로 연결해야 합니다.

각 조건 의미:

- `!그림자` — 그림자(보라 불꽃 배경) 제외
- `!정화` — 정화 포켓몬 제외 (그림자를 정화한 개체도 반짝이 표시가 있어서)
- `!다이맥스` / `!거다이맥스` — 맥스 포켓몬 제외
- `!배경` — 특수 로케이션 배경(이벤트 장소 배경) 달린 개체 제외
- `!코스튬` — 모자 쓴 피카츄 같은 코스튬 개체 제외

여기에 더 걸러내고 싶으면 뒤에 추가로 붙이면 됩니다:

- `&!행운` — 행운 포켓몬 제외
- `&!색이다른` — 이로치(색이 다른 포켓몬) 제외
- `&!전설&!환상` — 전설·환상 포켓몬 제외

전부 `&`로 이어 붙이면 조건이 모두 적용된 "아무 표시 없는 노말 개체"만 남습니다.

**이슈 1 (교차 확장자)** — 테스트가 검증한 케이스가 전부 **같은 확장자 조합**뿐입니다. `tdd-guard.test.js:35-42`를 보면 `covered.ts` + `covered.test.ts`, `nested.ts` + `__tests__/nested.test.ts` 두 케이스만 있고, `.ts` 소스에 `.test.tsx` 테스트가 있는 교차 조합은 아예 시나리오에 없습니다. 즉 테스트가 구현이 가정한 세계("테스트는 소스와 같은 확장자")를 그대로 복사해서 작성됐기 때문에, 그 가정 자체가 틀렸다는 걸 검증할 방법이 없었던 겁니다.

**이슈 2 (stdout/stderr)** — 테스트가 **exit code만 검사**합니다. `tdd-guard.test.js:19-20`에서 `r.status === expectedExit`만 비교하고, 차단 시 메시지가 어디로(stdout인지 stderr인지) 나가는지, 내용이 뭔지는 한 번도 확인하지 않습니다. 그래서 "차단은 되는데 사유가 모델에 안 보인다"는 결함은 이 테스트로는 원리적으로 잡을 수 없었습니다.
