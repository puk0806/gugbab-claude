**응답**

**private을 추천합니다.** 다만 DB가 있어서 그런 건 아닙니다.

**DB 때문에 private으로 해야 하는 건 아닙니다**
- DB 데이터는 Neon에 있고 레포에는 들어가지 않습니다.
- DB 접속 주소(`DATABASE_URL`)는 Vercel 환경변수와 로컬 `.env.local` 에만 두고, `.gitignore` 로 커밋에서 빼면 됩니다.
- 이것만 지키면 public이어도 DB가 노출되지는 않습니다.

**그래도 private을 추천하는 이유**
1. **회원 ID가 곧 비밀번호입니다.** 이 앱은 비밀번호 없이 ID만으로 들어오기 때문에, seed 파일이나 테스트 코드에 실제 ID가 한 번이라도 커밋되면 public 레포에서는 누구나 보고 들어올 수 있습니다. 나중에 지워도 git 기록에는 남습니다.
2. **실수 한 번이 치명적입니다.** `.env` 를 실수로 커밋하는 사고가 흔한데, public 레포는 비밀값을 긁어 가는 봇이 몇 분 안에 가져갑니다.
3. **잃는 게 없습니다.** GitHub private 레포는 무료입니다. Vercel Hobby도 private 레포를 그대로 배포합니다. 혼자 커밋한다면 제약이 없습니다.

**public이어도 되는 경우**
포트폴리오로 코드를 공개하고 싶다면 public도 괜찮습니다. 그때는 이렇게 하면 됩니다.

- `.gitignore` 에 `.env*` 를 넣습니다.
- GitHub secret scanning을 켭니다.

계획서에는 "private 레포, 실제 ID는 레포에 커밋하지 않음" 원칙으로 넣겠습니다. GitHub 레포를 만드는 건 승인 범위 밖이니, 사용자분이 요청하실 때만 하겠습니다. 계획서 작업 목록은 앞서 말씀드린 1~4 그대로입니다.
